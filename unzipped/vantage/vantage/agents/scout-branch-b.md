# Scout - Branch B Scan Rubric

This is the scoring sheet Scout applies to every candidate niche BEFORE
proposing a cluster. A cluster proposal goes to the Decision Queue only if
**all four gates pass**.

## Gate 1 - Demand (is anyone searching?)
- Identifiable buyer-intent queries (best X, X vs Y, X for [use case], X pricing)
- Volume evidence: marked ESTIMATE unless from a verifiable source
- Answer-engine gap check: do current AI answers cite weak/generic sources? (opportunity)

## Gate 2 - Competition (can a small site rank?)
- SERP not 100% dominated by big brands/well-known review sites
- Weak spots: thin content, outdated posts, forums/Reddit ranking (Reddit/Quora
  in the top 5 = Google is starved for quality answers)
- No YMYL wall (avoid health/finance/legal unless there's genuine expertise)

## Gate 3 - Monetisation (is there a live program?)
- At least one affiliate program that **accepts South African affiliates**
  (Awin / Impact / CJ / direct SaaS first; verify Amazon Associates SA
  eligibility before ever recommending it)
- Commission x realistic conversion = non-trivial ceiling, stated honestly
- Program actually converts (cookie window >= 30 days preferred, note it)

## Gate 4 - Feasibility (can we honestly write it?)
- Content can be written **without fabricated first-hand experience**
  (spec sheets, verifiable benchmarks, public pricing, objective comparisons)
- 3-5 test articles scoped in an hour of Scout thinking
- Not a dying trend that will be dead before the 4-6 week scoring window

## Scoring each gate: PASS / FAIL / THIN
- All PASS -> propose cluster (Decision Queue, type `new-cluster`, dossier attached)
- Any FAIL -> log the scan result in the activity feed ("scanned X, failed gate N") and move on
- THIN on <=1 gate -> propose ONLY if the other three are strong; flag the thin gate in the dossier

## Output cadence
- Per run: 1-3 candidate scans minimum; at least one genuinely bad candidate
  logged (honest negative results are data).
